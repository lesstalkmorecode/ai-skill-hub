# Herdr visible-team

Apply [Execution](execution.md) to actual visible Herdr worker panes; inherit runtime settings unless explicit overrides require [worker settings](../../../agents/model-routing.md). Use independent visible reviewers and track pane identities and results. Do not substitute internal subagents or invent commands. Manual worker selection applies only when requested.

**Literal diagnostic commands:** A user message such as `herdr status` means run that exact read-only Herdr command and report its result. Do not reinterpret it as `git status`, repository discovery, or a workflow/menu request. Run explicit diagnostic commands without requiring workflow or worker-setting selections; they do not start workers.

**Verify pane access:** Locate the installed `herdr` CLI, run `herdr status` and `herdr pane list`, and use server compatibility and pane IDs as evidence. Launching Codex from a Herdr pane, missing MCP tools or missing current-pane markers do not establish that control is unavailable: the CLI may still reach the server. Distinguish an unreachable server, unknown pane identity, unsupported commands and permission failures before declaring "outside Herdr". Status and listing verify read access, not permission or capability to mutate panes. Before mutations, consult the installed CLI help or `herdr --skill`. If control is confirmed unavailable, explain the failure and ask whether to switch modes.

If the shell reports `Failed to create unified exec process` or `setup refresh had errors`, the command did not execute. This is a command-runner/sandbox startup failure, not proof of missing Herdr or a disconnected pane. Avoid repeatedly retrying the same failing runner or switching to unrelated `git`/`rg` commands. If permitted by the environment, retry the same read-only diagnostic using its supported approval/escalation mechanism. Respect any denial; do not bypass permissions or change global configuration. If no working authorized runner is available, report that Herdr connectivity remains unverified and provide the exact diagnostic for the user to run in their Herdr pane.

**Codex launch flags:** Check the installed `codex --help` before constructing a visible worker command; use that version's supported arguments. Do not combine sandbox/approval shortcuts with conflicting explicit flags. Keep reviewers read-only and writers within the confirmed scope. Pass concrete model and effort choices through supported flags; for explicitly chosen inheritance omit those overrides and report the effective values as inherited when unknown. Never pass the literal preference value `inherit` as a model ID. Preserve organization requirements. When launch exits with an argument error, the worker never started: correct the flags before sending it a task, then verify its identity/state. Do not treat a running shell pane as a successfully started agent.
