# When work gets stuck

Read after a failed check, material review finding or repeated unsuccessful repair.

Before changing the model or sending another worker, identify whether the problem is missing information, a wrong assumption, excessive scope, unavailable tooling or reasoning difficulty. Inspect the failing behavior and supply the specific missing fact. Do not repeat the same approach without new evidence.

Give an authorized implementation worker a focused correction with the finding, affected behavior, current state and allowed checks. Reuse it while its context remains useful. Workers report failures; they do not upgrade themselves or launch replacement agents. Respect any user-set attempt or model limits across session changes.

Check the correction and affected dependencies against the new state. Required independent review must inspect the correction; retain earlier evidence only for unchanged behavior. A timeout does not authorize a duplicate writer.

When repairs repeat without progress, explain what was tried, what remains uncertain and a materially different next approach. Stop that unsuccessful loop and continue unaffected authorized work; ask for a user decision only when the next approach changes requirements, permissions or explicit constraints. Unresolved material findings cannot be reported as complete. Preserve the approved baseline in Spec-driven mode.
